---
title: "Evaluation model"
description: "Lazy, reader-driven recalculation and why edits stay cheap."
---

FormulaEngine never recalculates a whole workbook. Evaluation is **lazy** and
**reader-driven**: work happens when a value is requested, not when a cell is
edited.

## Edit time vs. read time

<Steps>
  <Step title="On edit">
    Parse the new content, diff its dependencies against the old ones, patch the
    dependency graph, and mark the cell and its dependents dirty. No formula is
    evaluated.
  </Step>
  <Step title="On read">
    `getCellValue()` walks the requested cell's prerequisites, evaluates the
    dirty ones in dependency order, caches the results, and returns the value.
  </Step>
</Steps>

The practical consequence: writing 10,000 formula cells is cheap. Reading one
of them evaluates only that cell's transitive inputs.

## Change detection

After a cell is recomputed, its new value is compared with the previous one.
If the value is unchanged, dependents are **not** invalidated — the propagation
stops there.

```typescript
engine.setSheetContent(
  sheet,
  new Map([
    ["A1", 10],
    ["B1", "=ROUND(A1/10)"], // 1
    ["C1", "=B1*100"],
  ]),
);

// A1: 10 -> 14 changes A1, but B1 still rounds to 1,
// so C1 is never recomputed.
```

This is what keeps large dependent chains from cascading on every keystroke.

## Caching

Evaluated values are cached and reused until an input actually changes.
Repeated reads are cheap:

```typescript
engine.getCellValue(addr); // evaluates
engine.getCellValue(addr); // cached
engine.getCellValue(addr); // cached
```

A UI can therefore call `getCellValue()` once per visible cell per render
without special-casing.

## Rendering a viewport

Because reads drive evaluation, "only compute what is on screen" needs no extra
API — just read the cells you are about to draw.

```typescript
for (let rowIndex = firstVisibleRow; rowIndex <= lastVisibleRow; rowIndex++) {
  for (let colIndex = firstVisibleCol; colIndex <= lastVisibleCol; colIndex++) {
    const value = engine.getCellValue({ ...sheet, colIndex, rowIndex });
    draw(colIndex, rowIndex, value);
  }
}
```

Offscreen formulas stay uncomputed until scrolled into view.

## Reacting to recalculation

`onUpdate` fires after a calculation cycle completes and returns an
unsubscribe function.

```typescript
const unsubscribe = engine.onUpdate(() => {
  rerender();
});

// later
unsubscribe();
```

In React, prefer the [`useSerializedSheet` hook](/guides/react), which wraps
this subscription.

## Cycles

A formula that participates in a reference cycle evaluates to the `#CYCLE!`
error rather than looping. See [Errors](/concepts/errors).
