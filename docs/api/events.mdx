## `onUpdate`

```typescript
onUpdate(listener: () => void): () => void
```

Registers a listener and returns an unsubscribe function.

```typescript
const unsubscribe = engine.onUpdate(() => {
  console.log("engine changed");
});

engine.setCellContent(a1, 42); // listener fires
unsubscribe();
```

Listeners fire after mutations, including undo and redo. The callback receives
no payload; read the cells or state your view needs.

<Note>
  Evaluation is lazy. The update means model state changed; call
  `getCellValue()` to compute and retrieve a new display value.
</Note>

## Rename events

Use resource-specific rename listeners when a consumer keeps a workbook or
sheet name as part of its local state:

```typescript
onWorkbookRename(
  workbookName: string,
  listener: (newWorkbookName: string) => void,
): () => void

onSheetRename(
  opts: { workbookName: string; sheetName: string },
  listener: (newSheetName: string) => void,
): () => void
```

Both rename methods return an unsubscribe function. A subscription follows the
same resource across later renames until it is unsubscribed. Sheet
subscriptions also follow renames of their containing workbook.

```typescript
const unsubscribeWorkbook = engine.onWorkbookRename(
  "Budget",
  (newWorkbookName) => console.log(newWorkbookName),
);

const unsubscribeSheet = engine.onSheetRename(
  { workbookName: "Budget", sheetName: "Q1" },
  (newSheetName) => console.log(newSheetName),
);
```

Callbacks run after a successful mutation commits, including undo and redo. If
a transaction performs multiple renames, listeners receive them in mutation
order after the transaction commits. Rolled-back renames do not notify.

## Delete events

Use the matching deletion listeners when a view needs to close or clear local
state after its resource disappears:

```typescript
onWorkbookDelete(
  workbookName: string,
  listener: () => void,
): () => void

onSheetDelete(
  opts: { workbookName: string; sheetName: string },
  listener: () => void,
): () => void
```

Delete subscriptions follow workbook and sheet renames just like rename
subscriptions. Deleting a workbook notifies both its workbook listener and the
sheet listeners for every sheet it contained.

Callbacks run after commit whenever a resource is removed. This includes a
direct remove, redoing a remove, and undoing an add. Restoring a deleted
resource does not fire a delete callback, and rolled-back deletes do not
notify.

## `getState`

```typescript
getState(): {
  workbooks: Map<string, Workbook>;
  namedExpressions: unknown;
  tables: Map<string, Map<string, TableDefinition>>;
  conditionalStyles: ConditionalStyle[];
  cellStyles: DirectCellStyle[];
  rangeMetadata: RangeMetadata[];
  references: unknown;
}
```

The exact inferred generic types depend on your engine metadata type. Treat the
result as a snapshot for observation, not a mutation surface.

## React

`onUpdate` maps directly to `useSyncExternalStore`:

```tsx
function useFormulaEngine(engine: FormulaEngine) {
  return useSyncExternalStore(
    (notify) => engine.onUpdate(notify),
    () => engine.getState(),
    () => engine.getState(),
  );
}
```

The companion `FormulaSheet` and `FormulaWorkbook` components already subscribe
internally.

For a component that stores resource names directly, subscribe to the rename
events as well:

```tsx
const [workbookName, setWorkbookName] = useState("Budget");
const [sheetName, setSheetName] = useState("Q1");
const [sheetDeleted, setSheetDeleted] = useState(false);

useEffect(
  () => engine.onWorkbookRename(workbookName, setWorkbookName),
  [engine, workbookName],
);

useEffect(
  () =>
    engine.onSheetRename(
      { workbookName, sheetName },
      setSheetName,
    ),
  [engine, workbookName, sheetName],
);

useEffect(
  () =>
    engine.onSheetDelete(
      { workbookName, sheetName },
      () => setSheetDeleted(true),
    ),
  [engine, workbookName, sheetName],
);
```

## Persist on change

For small models, serialize on every update:

```typescript
const unsubscribe = engine.onUpdate(() => {
  localStorage.setItem("model", engine.serializeEngine());
});
```

For large workbooks, debounce the write:

```typescript
let timer: ReturnType<typeof setTimeout>;
const unsubscribe = engine.onUpdate(() => {
  clearTimeout(timer);
  timer = setTimeout(() => save(engine.serializeEngine()), 500);
});
```

## History state

`getUndoRedoState()` is separate from `getState()`:

```typescript
const {
  canUndo,
  canRedo,
  undoDepth,
  redoDepth,
  maxDepth,
} = engine.getUndoRedoState();
```

Call it in an update listener to keep toolbar controls current.

## Listener lifecycle

- keep the returned unsubscribe function
- unsubscribe when a component unmounts
- avoid registering the same callback repeatedly
- do not mutate the engine from a listener unless you explicitly want a second
  update cycle
