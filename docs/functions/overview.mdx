FormulaEngine currently registers **47 functions** across seven categories, plus
two aliases: `CONCAT` for `CONCATENATE` and `COLS` for `COLUMNS`. That makes 49
function names. Function names are case-insensitive in formulas.

| Category | Functions |
| --- | --- |
| [Math](/functions/math) | `SUM`, `SUMIF`, `SUMIFS`, `AVERAGE`, `AVERAGEIF`, `AVERAGEIFS`, `MIN`, `MINIF`, `MINIFS`, `MAX`, `MAXIF`, `MAXIFS`, `CEILING`, `INT` |
| [Logical](/functions/logical) | `IF`, `IFERROR`, `AND`, `OR`, `LET` |
| [Text](/functions/text) | `CONCATENATE`, `CONCAT`, `EXACT`, `FIND`, `LEFT`, `RIGHT`, `MID`, `LEN`, `TEXTJOIN` |
| [Lookup](/functions/lookup) | `COUNT`, `COUNTA`, `COUNTIF`, `COUNTIFS`, `INDEX`, `MATCH`, `XLOOKUP` |
| [Array](/functions/array) | `SEQUENCE`, `UNIQUE`, `TOCOL`, `TOROW`, `HSTACK` |
| [Information](/functions/information) | `CELL`, `COLUMN`, `COLUMNS`, `COLS`, `ROW`, `ROWS` |
| [Reference](/functions/reference) | `ADDRESS`, `INDIRECT`, `OFFSET` |

## Formula syntax

Cell formulas begin with `=`:

```typescript
engine.setCellContent(address, "=SUM(A1:A10)");
```

Function arguments use commas. Strings use double quotes inside formula source:

```typescript
engine.setCellContent(address, '=IF(A1>10,"large","small")');
```

Named-expression definitions are the exception: their `expression` omits the
leading `=`.

### Omitted arguments

An argument can be left out by writing nothing between its commas:

```excel
=SEQUENCE(,3)   // rows omitted: one row, 1,2,3
=SUM(1,,2)      // 3
```

Many functions with optional parameters follow Excel's rules for an omitted
argument. Most use the parameter's default, as `SEQUENCE` does for its `rows`,
`columns`, `start` and `step`. Where Excel reads the omitted argument as `0`,
so does this engine: `=MATCH(25,B2:B6,)` is an exact match, `=LEFT("North",)`
is empty text, and `=IF(A1,,"x")` returns `0` when `A1` is true. Each
function page describes these cases.

In other functions, such as `SUM`, `COUNT`, `CONCATENATE` and the `*IF`
family, an omitted argument reads like a reference to an empty cell, so `SUM`
skips it. Excel reads it as `0`, so results can differ where a function treats
an empty cell differently from `0`: in this engine `=COUNT(1,,2)` is `2`, where
Excel returns `3`.

`F()` is a call with no arguments, not a call with one omitted argument. Array
literals don't accept omitted elements: `{1,,2}` is a syntax error.

## Values and ranges

Most aggregate functions accept any mix of scalars and ranges:

```excel
=SUM(1, 2, A1:A10)
=MAX(A:A)
=AVERAGE(Sheet2!B2:B20)
```

Whole-column and whole-row ranges are sparse; the engine visits populated cells,
not every possible address.

## Criteria syntax

The `*IF` and `*IFS` families use spreadsheet criteria strings:

```excel
=SUMIF(A2:A10,"North",B2:B10)
=COUNTIF(B2:B10,">=100")
=AVERAGEIFS(C2:C10,A2:A10,"North",B2:B10,">0")
```

Criteria can be literals or comparison strings. Multi-criteria functions use
`criteria_range, criteria` pairs.

## Comparing text

The comparison operators are strict about type and case. `=` and `<>` compare
text case-sensitively, and `<`, `>`, `<=`, `>=` accept only numbers, so text on
either side gives `#VALUE!`. Excel compares text case-insensitively and orders
it alphabetically.

Given `NP` in `A1`:

```excel
=A1="NP"     // TRUE
=A1="np"     // FALSE   (Excel: TRUE)
=A1<>"np"    // TRUE    (Excel: FALSE)
="a"<"b"     // #VALUE! (Excel: TRUE)
=EXACT(A1,"NP") // TRUE
```

Lookup and criteria matching does not follow the operators. With `NP`, `x` and
`np` in `A1:A3`:

| Case-insensitive, as in Excel | Case-sensitive |
| --- | --- |
| `COUNTIF(A1:A3,"np")` is `2`, and so are the other `*IF` and `*IFS` criteria | the `=` and `<>` operators |
| `MATCH("np",A1:A3,0)` is `1` | `XLOOKUP("np",A1:A3,…)` finds `A3` |
| `UNIQUE` folds `"a"` and `"A"` into one entry | `EXACT`, `FIND` |

A workbook that compares a cell with text written in a different case, such as
`=IF(A1="np",…)` against data containing `NP`, needs the literal to match the
data exactly.

## Array results

`SEQUENCE`, `UNIQUE`, `TOCOL`, `TOROW`, `HSTACK`, range references, array
literals, `INT` over an array, and operators or `IF` applied to arrays may
spill into neighbouring cells. Operators and `IF` broadcast arrays of
different shapes the way Excel does, so `=SEQUENCE(3)*SEQUENCE(,4)` spills a
3 × 4 multiplication table. A blocked output area produces `#SPILL!` until the
blocking content is removed. See [Spilling](/concepts/spilling).

Aggregates accept these results directly:

```excel
=SUM(SEQUENCE(4)/2)                       // 5
=SUM(HSTACK(SEQUENCE(2), SEQUENCE(2)*10)) // 33
```

## Errors

Unknown function names return `#NAME?`. `IFERROR` catches error values, with one
important exception: division by zero currently returns the string `"INFINITY"`
rather than an error, so it is not caught. See [Errors](/concepts/errors).

<Note>
  Functions familiar from Excel but absent from the table above are not
  registered. For example, `VLOOKUP`, `VSTACK`, `SQRT`, `NA` and `UPPER`
  currently return `#NAME?`.
</Note>
